Overview

Tewahedo Daily is a React and TypeScript companion for Ethiopian Orthodox prayer, chant practice, and the Church calendar. Each day opens to that day's date in both the Ethiopian and Gregorian calendars, with shortcuts to Scripture, prayers, hymns, and the calendar.

The opportunity

Prayers, Mezmur (hymns), saints, feasts, and teachings are spread across books, recordings, and websites. The goal was one daily destination that works on a phone, supports more than one language, and lets trusted editors publish and review content.

Objectives

  • Make daily prayer, Scripture, hymns, and the calendar reachable in one or two taps.
  • Support practice, with chant pages, persistent audio, and favorites for signed-in users.
  • Give administrators a safe way to publish saints, feasts, prayers, and articles.

The solution

A Vite-built progressive web app hosted on Cloudflare Pages, with Pages Functions for server-side tasks. Supabase provides authentication, Postgres storage, and row level security, so the public can only read published content while all writes go through trusted server or command-line environments. A separate FastAPI service powers search assistance, and the app still works from bundled JSON data during local development.

Features delivered

  • Daily home page with Ethiopian and Gregorian dates and previous, today, and next day navigation.
  • Libraries for saints, feasts, prayers, and teachings, with published detail pages.
  • Mezmur practice pages with pagination, multilingual search, discovery filters, and persistent audio.
  • Signed-in favorites and site-wide search across published content.
  • An admin CMS with role-aware access, media uploads, and dated home page selections.
  • Reviewed community submissions protected by a bot check.

Design and development decisions

  • Least privilege by default. The browser only ever receives a publishable key; secret keys stay in trusted environments.
  • Safe content migration. Importers run as dry-run reports first and leave source data untouched.
  • Separate front end and backend deployments. Static hosting builds only the front end, so the backend and private content are never published by accident.
